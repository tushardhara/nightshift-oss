## 2. Acceptance criteria

1. **RT-16 test class exists** at a fully-qualified dotted node id, runnable as
   `python3 -m unittest -v <node_id>` from a stated `cwd` (`root` or `tests`), green, zero skips,
   `testsRun > 0`.
2. **RT-16 negative case**: constructs (directly, via `deploy/policies/omnipods_policies.py`'s
   `worker_semaphore()` factory/evaluator, not a shell-level proxy) a `sys_session_send`-shaped
   `tool_call` event for a counted agent (`engineer`/`qa`/`reviewer`) or an on-call agent, in a
   control-plane fixture (temp sqlite db, same shape as `tests/test_admission_gate.py`'s
   `AdmissionFixture`) where **no** `worker_slots` row is `active`, `dispatched_at IS NULL`, and
   matching `(kind, expected_agent, expected_title, expected_purpose)`. Asserts the evaluator
   returns a denial (not the `_ALLOW` sentinel) with a non-empty reason string.
3. **RT-16 consumed-slot case**: same fixture, but the matching row exists and already has
   `dispatched_at` set (i.e. previously consumed). Asserts denial — proves "unconsumed" is
   actually checked, not merely "exists".
4. **RT-16 positive control**: same fixture, with a genuinely live, bound, unconsumed matching row
   (created the same way `nightshift-ctl slot acquire` creates it). Asserts the identical event is
   allowed exactly once, and a second identical dispatch attempt immediately after is denied
   (one-use). Without this control, criteria 2-3 could pass against a evaluator that always
   denies — a test that cannot fail is worse than none.
5. **RT-17 test class exists** at a fully-qualified dotted node id, runnable standalone, green,
   zero skips, `testsRun > 0`.
6. **RT-17 exercises concurrent, independently produced acquisitions against one shared control
   plane**: at least 12 contenders spanning more than one crew, holder and task, each a real
   `bin/nightshift-ctl` subprocess (`tests/ctlutil.py` `Ctl`/`run_parallel`), against the **same**
   temp control.db + capacity.json fixture, running concurrently — not serialized by the test
   itself. The property under test is **convergence**: independently produced acquisition attempts
   resolve against one atomic budget. Caller identity is deliberately **not** a variable, because
   the normal-slot path does not read it (`bin/nightshift-ctl:1469-1480` selects `holder`/`crew`
   for the denial payload only; the grant decision reads `kind`, `phase` and active-row counts).
   The test MUST NOT encode a producer distinction in task ids, titles, holder labels, or
   test/class names, since the code never reads them and doing so would imply evidence that does
   not exist.
7. **RT-17 fixture is hermetic**: a temp `.omni/capacity.json`-equivalent with explicit,
   test-declared `max_concurrent_workers` and `reserve_for_oncall` values (not read from the live
   repo `.omni/capacity.json`, and not assumed to match whatever a deployed host currently runs —
   see §0's host/repo drift finding).
8. **RT-17 budget assertion**: across all concurrent acquires in the run combined — whatever
   crew, holder or task produced them — the number of simultaneously-granted `normal`-kind slots
   never exceeds `max_concurrent_workers − reserve_for_oncall` for the fixture's own numbers.
   This is criterion 6's **convergence** property measured on the budget: it must hold over the
   combined set of contenders, and must not be stated — in the test, in any capture, or in a test
   or class name — as a claim about distinct caller or producer paths. Observation set, stated so
   this is objectively checkable rather than a matter of judgement: every acquire attempt's own
   return code and response body, plus a `slot list` after the run. The bound must hold at each
   of those points, not only the last.
9. **RT-17 reserve assertions — both directions.**
   (a) At saturation, a `normal`-kind acquire is denied (exit 3, `worker budget exhausted`) rather
   than encroaching on the reserve, and an `oncall`-kind acquire presenting a live,
   current-generation Program authority token succeeds from the reserve.
   (b) An `oncall`-kind acquire that does **not** present a valid authority token is denied, exit 3,
   deterministically — covering at minimum a missing token, and either a wrong token or a stale
   generation. This is the ONLY point in the slot path where caller identity is mechanically
   enforced (`bin/nightshift-ctl:1415-1432`, ADR-0044 §3b), so it is the only place a caller-shape
   claim can be made honestly; without (b), the gate is never shown capable of refusing.
10. **RT-17 overflow is a denial, not silent queuing or silent over-grant**: the acquire call that
    would exceed the budget returns a non-zero/denied result deterministically (asserted on every
    run, not flaky under thread scheduling) — use the existing `Ctl`/virtual-clock harness idioms
    from `tests/test_slots.py` to make this deterministic.
11. **Evidence obligation — at least one regression**: at least one of RT-16 / RT-17's baseline
    records must be captured with `exit_code != 0` at a real pre-fix ancestor SHA (a `regression`
    per `tests/dod_validate.py:369`'s derivation) — never both `preservation`. This is mechanical:
    `check_d08` (`tests/dod_validate.py:527-529`) and `generic_rt_condition`
    (`tests/dod_validate.py:...415`) both independently fail condition 6 outright if every
    satisfied RT id for it is `preservation`. Which of the two ids is the regression is **not**
    decided by this spec — it is discovered empirically by running each test at candidate ancestor
    SHAs. (§0's finding — that the crew-lead path has no mechanical slot-consumption gate mirroring
    `worker_semaphore` — makes RT-17 the more likely regression candidate, but the builder must
    verify this by actually running the test, not assume it.)
12. **Evidence obligation — preservation carries a kill**: whichever RT id is captured with
    `exit_code == 0` (a `preservation` record) must additionally carry a `mutations` array with at
    least one entry: a committed patch (`docs/audit/baseline/RT-1x.mutant.patch`) applied at an
    ancestor SHA that is an ancestor of HEAD, touching only that id's declared `binding.file`, run
    with the byte-identical baseline `command`, producing a captured non-zero exit code
    (`docs/audit/baseline/RT-1x.mutation.txt` or equivalent). (`tests/dod_validate.py:390-397`,
    `_validate_mutation` at line 308.)
13. **Every test must have a demonstrated failure mode** — "a test that cannot fail is worse than
    none": for the regression id, the pre-fix capture at its `baseline_sha` showing the test
    genuinely fails IS that demonstration; for the preservation id, the mutant kill (criterion 12)
    IS that demonstration. A test class with neither is not acceptable evidence regardless of
    whether `python3 tests/dod_validate.py`'s structural checks would pass it.
14. **`baseline_sha` (and, where present, `mutations[].applied_to_sha`) must be real ancestors of
    HEAD** (`git merge-base --is-ancestor <sha> HEAD` exits 0), and must be SHAs at which the
    named test's outcome genuinely differs the way the record claims — not an arbitrary early
    commit picked for convenience.
15. **`binding.file` for RT-16 is `deploy/policies/omnipods_policies.py`** — the file whose
    `worker_semaphore` evaluator the test actually calls, and it must exist at HEAD.
16. **`binding.file` for RT-17 is `bin/nightshift-ctl`** — the file whose `cmd_slot_acquire` /
    capacity arithmetic the test actually drives via subprocess, and it must exist at HEAD.
17. **Output captures land under `docs/audit/baseline/`, non-empty**, one per RT id
    (`RT-16.txt`/`RT-17.txt` or equivalent), plus mutant patch/output pairs for whichever id is
    preservation, following the exact file layout already used for `RT-11` and `RT-18` in that
    directory (`patch_path`/`output_path` both resolve inside `docs/audit/baseline/`).
18. **No change to `docs/prd/DOD-MANIFEST.json`** in this task's diff. STEP 2 (manifest wiring,
    lease held by `product`) is a separate, later task.
19. **No change to production behaviour** in this task's diff — `deploy/policies/omnipods_policies.py`
    and `bin/nightshift-ctl` at HEAD are read and exercised, not modified, by this task (mutant
    patches are committed as inert `.patch` files under `docs/audit/baseline/`, never applied to
    the tracked source).

## 3. Failure / empty states

- **RT-16, no matching slot**: evaluator denies with a reason string naming "no active undispatched
  slot matches" (or equivalent non-empty reason) — never a silent `_ALLOW`, never an exception that
  escapes as an unhandled error (the production code raises `ValueError` inside a `try` that the
  caller turns into a structured deny — the test asserts the structured deny, not a raw exception).
- **RT-16, ambiguous (>1) matching slot**: evaluator denies (existing `ValueError` "ambiguous
  dispatch identity" path) — covered incidentally if the fixture ever produces this shape, not a
  required separate criterion, but must not be silently allowed if it occurs.
- **RT-17, budget exhausted**: the acquire call that would exceed the normal-slot budget returns a
  denial/non-zero result, deterministically, not a hang, not a silent grant, not an unbounded queue.
- **RT-17, reserve requested by a normal-kind caller**: denied, deterministically, whatever crew,
  holder or task the acquire carries. The reserve is unreachable by any `normal`-kind acquire; it
  is reachable only by an `oncall`-kind acquire presenting a live, current-generation Program
  authority token, and an `oncall` acquire without one is denied exit 3 (criterion 9(b)).
- **RT-17, control plane missing/corrupt**: out of scope for this task — `worker_semaphore`'s
  existing fail-closed behavior on a missing `.omni/control.db` (`deploy/policies/omnipods_policies.py:243-251`)
  is pre-existing, already production behavior, and not part of what RT-16/RT-17 are chartered to
  newly prove; do not add assertions about it under these node ids.

## 8. Spec bug found in the charter's framing

Issue #507's own "Done when" section says D06 is done when, among other things, *"the manifest's
`docs/prd/DOD-MANIFEST.json` `rt_ids` section binds them to condition 6 with a real baseline
capture, and `tests/dod_validate.py`'s D06 check reports PASS."* That is the issue-level
definition of done for **#507 as a whole**, but the task charter for *this* sub-task

after STEP 2 lands — not this task's. Whoever signs off this task's PR should accept "STEP 2 not
yet done" as expected, not as a gap in this PR, and should not ask this task's implementer to touch
the manifest to make `dod_validate.py` go green.

## 9. Version history

**v1 → v2, 2026-09-02, product (crew_alpha). Trigger: PR #585 review finding F1, independently confirmed by QA as PRE_DEPLOYMENT.**

v1 criterion 6, verbatim: *"RT-17 exercises two distinct caller shapes concurrently against one shared control plane: (a) a program-shaped acquisition sequence and (b) a crew-lead-shaped acquisition sequence (per `program/agents/crew_alpha/config.yaml:103`'s own described flow: `slot acquire` then a named `sys_session_send`), both driven as real `bin/nightshift-ctl` subprocesses …"*

**Reason changed:** not provable at this layer, and internally contradictory. It required two distinct caller shapes AND that both be driven as `nightshift-ctl` subprocesses; the normal-slot path reads no caller identity, so the only way to satisfy the letter of v1 was to encode the distinction in labels the code never reads. PR #585 did exactly that in good faith and disclosed it (ADR-0069 §5). A criterion satisfiable only by decoration is worse than no criterion: it would mark DoD condition 6 satisfied on evidence that does not exist. v2 names the property that IS real — convergence on one atomic budget — and explicitly forbids the label-encoded substitute.

v1 criterion 9, verbatim: *"a `normal`-kind acquire from either caller shape, at saturation, is denied rather than encroaching on the reserved on-call pool; an `oncall`-kind acquire succeeds from the reserve. (Mirrors `tests/test_slots.py`'s existing reserve check, but across both caller shapes instead of one uniform pool.)"*

**Reason changed:** the "both caller shapes" clause inherited criterion 6's defect, but the underlying aim was sound and aimed at the one branch where caller identity IS enforced. v2 drops the unprovable clause and **adds** the negative case v1 never asked for, so the authority gate is shown able to refuse and not merely to permit. This is a tightening, not a relaxation.

**Criterion 13 is NOT restated and is not weakened.** It remains: every test must have a demonstrated failure mode. Clarification only, adding no latitude: a test that cannot be captured at a pre-fix ancestor discharges criterion 13 by carrying a mutant on its own `binding.file`, per criterion 12's mechanism. "It is covered by the class's other tests" does not discharge it.

**Residual, stated so nobody reads RT-17 as proving more than it does:** real external program-vs-lead routing convergence — whether the harness actually routes both producer paths through this CLI — is **not** proven by RT-17 and never was. It is covered by QA's PRE_DEPLOYMENT integration probe and disclosed in ADR-0069 §5. RT-17 proves that acquisitions which reach the CLI share one atomic budget. It does not prove that all of them reach it. Anyone binding RT-17 as evidence for a broader claim is misreading it.
