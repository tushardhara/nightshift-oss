READ THIS BEFORE TRUSTING THE NUMBER — THREE DISCLOSURES
--------------------------------------------------------
1. SUBTEST INFLATION. The 11 failures are NOT 11 independent findings: they are
   8 distinct test METHODS, because
   `test_rt30_the_check_itself_detects_a_root_that_DOES_cover` contributes 4
   subTest failures (one per candidate root: `~`, `~/.config`,
   `~/.config/omnigent`, and the absolute form) and every other failing method
   contributes exactly 1. 4 + 7 = 11. Counted honestly the evidence is 8
   methods, not 11, and "Ran 14" is 14 methods since subTests do not increment
   that total.

2. THE HARNESS MOVED, SO SOME FAILURES ARE THE HARNESS, NOT THE DEFECT.
   `Box` now resolves state from `$HOME/.config/omnigent` and sets
   `XDG_STATE_HOME` to a DECOY. Against the unmodified script — which still
   reads `${XDG_STATE_HOME:-$HOME/.local/state}` — the attestation is written
   somewhere the script does not look. That is a true statement of the defect
   (producer and consumer resolve differently), but it means these failures
   would NOT all be reproduced by the new tests alone on the old harness. Said
   plainly so nobody counts them as independent evidence.

3. **RT-30's HEADLINE ASSERTION DOES NOT FAIL AT BASELINE, AND I AM NOT
   CLAIMING IT DOES.** `test_rt30_the_attestation_is_under_no_configured_
   writable_root` PASSES here, for two independent and equally uninteresting
   reasons: `nightshift_sandbox_grants_path` does not exist yet, so the helper
   returns "not granted" for everything; and the assertion is written against
   the POST-MOVE path, which the old roots would not cover anyway. A passing
   security assertion that passes because the checker is blind is worth
   nothing, and this is exactly the "206 OK" laundering I refused elsewhere.
   What DOES fail is its vacuity guard,
   `test_rt30_the_check_itself_detects_a_root_that_DOES_cover` (4/4 subTests),
   which is in the file precisely so that a blind checker cannot be mistaken
   for a secure one. RT-30's real pre-change evidence is the MEASUREMENT in
   `security`'s re-review (200 ticks, agent refreshes both stamps, 200/200
   silent) plus the pinning test added with the fix, which asserts the checker
   reports GRANTED for the pre-move arrangement (`~/.local/state` + the old
   path). Read RT-30 as "invariant now enforced and the enforcer is proven
   able to say no", not as "a red test turned green".
