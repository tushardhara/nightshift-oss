**The true baseline split is 5 PASS / 3 FAIL.** The three that fail are
`..._never_started_box_does_not_alert`,
`..._run_current_is_asked_of_the_PROJECT_control_plane` and
`..._install_then_start_then_first_beat`.

1. THE COUNT. 3 of 8, not 4 of 8. The original capture was taken against the
   PRE-F2 harness; F2 later moved the state directory, and with it the path
   `Box.marker_exists()` reads. The archived 4th failure was GENUINE THEN and is
   INVISIBLE TO THE SHIPPED ASSERTION NOW: against the pre-F2 harness
   `marker_exists()` read the XDG path the script actually wrote, so that
   failure was real evidence that the baseline burned the re-alert window - the
   behaviour point 2 below re-measures and confirms. It does not reproduce
   because the assertion moved, not because the box behaved differently. Read
   "does not reproduce" as "the shipped test can no longer see it", never as
   "it never happened".

2. THE FLIPPED ASSERTION PASSES **VACUOUSLY**, AND IS NOT EVIDENCE.
   `test_rt27_never_started_box_does_not_burn_the_realert_window` passes at this
   baseline for the wrong reason entirely. `Box.marker_exists()` resolves
   `$HOME/.config/omnigent/watchdog-last-alert` — the POST-F2 path — while
   `Box.run()` deliberately points `XDG_STATE_HOME` at a decoy, and the 7c16fbe
   script resolves `STATE_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/omnigent"`.
   Producer and consumer resolve to different directories, so the check reads a
   directory the script never writes.

   MEASURED at this baseline, same setup as the test:

       alert_count()                            -> 1
       marker_exists()  ($HOME/.config/omnigent)-> False
       files under the XDG decoy                -> $XDG_STATE_HOME/omnigent/
                                                     watchdog-last-alert

   The box **did** alert and the re-alert window **was** burned. The marker
   landed in the decoy, so `assertFalse` passed. "No marker was burned" is the
   right answer read off the wrong directory.

   It is therefore disclosed, not counted — in EITHER direction. It is not a
   pre-fix failure, and it is equally not a pre-fix pass that proves anything.
   The 4 remaining passes ARE meaningful: they are the fail-closed guards (a
   recorded run with no beat still alerts, an unreadable plane still alerts,
   non-`missing` reasons are never graced, the alive path asks no second
   question), and they are what stops this fix degenerating into "delete the
   `missing` alert".

3. WHAT IS UNAFFECTED. The headline evidence for #34 stands on its own and was
   re-measured: `..._never_started_box_does_not_alert` and
   `..._install_then_start_then_first_beat` both fail at this baseline, exit_code
   is 1, and the derived kind is still `regression`. The correction narrows the
   claim; it does not withdraw it.
