WHY THE OTHER THREE FAILURES EVAPORATED. The harness moved under this record.
F2 relocated the state directory, so the shipped tests plant the attestation at
`$HOME/.config/omnigent/bootstrapped-at`, while the 86efd26 script still reads
`STATE_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/omnigent"` — and `Box.run()`
points `XDG_STATE_HOME` at a decoy. The old script therefore finds **no
attestation at all**, takes `installer_at=0`, fails the gate on the FIRST
conjunct and alerts. `alert_count == 1` is what the assertions want, so
`..._a_garbled_attestation_alerts` (all 7 subTests) and
`..._cannot_rescue_an_ESTABLISHED_box` now PASS — **the right outcome via the
wrong cause.** They never exercise the future date at all.

THE ONE SURVIVING FAILURE ALSO FAILS FOR A DIFFERENT REASON THAN ARCHIVED.
`..._gets_its_OWN_operator_story` still fails, but not as recorded below. The
archived traceback is `'never_started' not found in ''` at line 1074 — an EMPTY
body, i.e. no alert whatsoever. Re-run, it fails at line 1119 on
`assertIn("future", ...)` against a FULL `never_started` body whose text is the
no-attestation story. Same verdict line, different mechanism. It is not
independent confirmation of F1 either.

F1 IS REAL, AND HERE IS THE REPRODUCTION THAT ACTUALLY SHOWS IT.
The defect is in the SCRIPT, so exercise the script, and plant the attestation
where the script under test actually reads it. Established box (bootstrapped
long ago), control plane restored, Program dead, `run current` -> exit 3,
attestation written to BOTH candidate paths so path resolution is not the
variable and only the DATE varies:

    attestation date        deploy/ @ 86efd26      deploy/ @ 9cb87ba (head)
    ----------------------  ---------------------  ------------------------
    +48h   (future)         posted = 0  SILENT     posted = 1  alerts
    +10y   (future)         posted = 0  SILENT     posted = 1  alerts
    -30d   (established)    posted = 1  alerts     posted = 1  alerts
    -1h    (fresh install)  posted = 0  silent     posted = 0  silent

The two controls are identical on both sides: an established box still alerts,
a genuinely fresh one is still graced. Only the future-dated rows move. That is
F1 exactly — `now - installer_at` goes NEGATIVE and a negative number is
unconditionally less than the grace window, so a future date was the one input
that could never fail the gate, and it bought silence forever. The `-le "$now"`
conjunct is what closes it.
