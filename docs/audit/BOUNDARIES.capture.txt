5. GitHub credential scope -- Q2 (docs/TRUST-BOUNDARY.md:43 claims "fine-grained PAT scoped to
   the ONE project repo... Never a classic PAT, never org-wide") -- F-2
   NOTE: `gh auth status` prints the token PREFIX AND SCOPES ONLY; it never reveals the token
   value. This is the safe, standard way to inspect token shape without exfiltrating the secret.
=====================================================================
$ gh auth status
github.com
  - Logged in to github.com account tushardhara (/home/nightshift/.config/gh/hosts.yml)
  - Active account: true
  - Git operations protocol: https
  - Token: gho_************************************
  - Token scopes: 'gist', 'project', 'read:org', 'repo', 'workflow'

Result: the live token carries the `gho_` prefix, which is a GitHub OAuth App (`gh auth login`
device-flow) token, not a fine-grained PAT (`github_pat_...`). Its `repo` scope is the CLASSIC,
account-wide repo grant (every repository the account can access), not a fine-grained grant
scoped to one repository -- there is no fine-grained-PAT mechanism that expresses "one repo"
within an OAuth App token's scope list at all. `read:org`/`gist`/`project` are also broader than
"the one project repo".
