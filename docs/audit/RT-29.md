### On C2 and the first fixture that did not reproduce

**My first attempt at C2 did not reproduce the fail-open**, and the reason is worth
keeping. Without `run current --set rt29`, `beat show` returned
`{"alive": false, "reason_code": "no_expected_run"}` — exit 3 — *even under the pinned
clock*, because a different guard fired first: it refuses to report alive on a
heartbeat whose run it cannot verify. That is the plane fail-closing correctly, and it
would have been easy (and wrong) to write "could not reproduce, `security` overstated
it" on the strength of it.

The correct reading is the one ADR-0005 already states: `wrong_run` and `wrong_boot`
**do not catch this**, because in the scenario the watchdog exists for — the real
Program, the real run id, the same host — both match. Setting the expected run is not
tuning the fixture until it goes red; it is *removing the guards that do not apply* so
that the age check is the only thing left, which is precisely the production
configuration. With the run recorded, the fail-open reproduced on the first try.

**Both fixture states are in the capture**, so you can judge this yourself rather than
take the paragraph above on trust: §2 is the reproducing form, and **§10 is the
non-reproducing first attempt**, re-run and kept on purpose. §10 is the more
interesting half — under the pinned clock `age` does drop to `0.0`, proving the clock
*was* injected, while `alive` stays `false` at exit 3 because `no_expected_run` fires
first. The channel was live in both; only the guard downstream of it differed.

### The retracted RT-26 failure — recorded, not hidden

Earlier in this task I reported an `RT-26 … FAILED (errors=4)`. **That failure was not
real.** It was an artifact of how I invoked the suite, I diagnosed it as such, and I
retracted it in the same report rather than re-running until it went green. It is in
this record because an evidence file that quietly drops a retracted failure is exactly
the laundering this project exists to stop.

**What I can still show** (§9 of the capture): this suite is CWD-sensitive, which is
the class the false alarm belonged to. From the repo root,
`python3 -m unittest -v tests.test_recovery` dies at import with
`ModuleNotFoundError: No module named 'ctlutil'` → `FAILED (errors=1)`; a bare
`python3 -m unittest discover` from the root reports `NO TESTS RAN`. The sanctioned
invocation, `cd tests && python3 -m unittest …` (and `tests/run.sh`), is green.

**What I cannot show, stated plainly: the exact argv of the original false alarm was
not preserved,** so I could not reproduce `errors=4` exactly and I did not go looking
for an invocation that would produce that number — manufacturing a matching failure
after the fact is the same defect as manufacturing a passing one. The lesson is
mechanical and goes to the retro: **capture the command with the failure, in the same
buffer, always.** A failure without its argv cannot be re-judged by anyone, including
its author.

## Unplanned: #31 reproduced on the author, mid-capture (§11)

This was not part of the plan and it is the most useful thing in the record.

Looking for slot 35, I ran the **pre-fix** build — `a73ba88`, the checked-out build of
the `/home/nightshift/nightshift-runtime` clone — from that clone's root. It
manufactured an empty control plane as a side effect of `slot list`, and I read
`{"active": []}` and `{"leases": []}` and briefly believed my slot and my lease were
gone. The real plane, with 37 slot rows and 12 lease rows, is
`/srv/project/.omni/control.db`. **It answered. It did not error.** That is the whole
severity argument of #31, delivered to the person writing the file about it.

The forensics are in §11: file **birth time `2026-08-23 04:33:38`** — the minute of my
first command against that directory, so the artifact is mine and not pre-existing —
`?? .omni/` (untracked, not a fixture), all ten tables at **0 rows** against the real
plane's 37/12/2, and every worktree of that clone resolving to it.

Two things follow, and the second is a correction to this PR's own ADR:

1. **The artifact was removed** (`rm -rf /home/nightshift/nightshift-runtime/.omni`),
   restoring the pre-04:33:38 state. §11 shows the loud `control_plane_missing`
   refusal returning afterwards — carrying, in the real scenario it was written for,
   the exact hint text this same commit corrects in ADR-0005 D2. The real plane was
   verified unharmed.
2. **ADR-0005 D1 claimed too much and is corrected in this commit.** It said discovery
   can only find a plane "someone already created **deliberately**". Nobody created
   this one deliberately; a pre-fix binary created it as a side effect. D2 stops a
   phantom being *manufactured* by this build; it does not stop one already
   manufactured from being *adopted*, and pre-fix binaries still exist on this host
   (issue #42). The fix is necessary and it is not sufficient while they do.
