## What changed

- **`deploy/nightshift-scheduled-run-detector.py`**: `_process_run`'s raw
  run-status set now accepts `"standdown"` in addition to
  `scheduled/running/succeeded/failed/skipped`. Before this change, a
  Program that lost the ADR-0044 authority race and recorded its run via
  `nightshift-ctl schedule observe --status standdown` would make every
  later poll of that run a hard `DetectorError("run returned an
  unsupported status")`, exit 1. `INCIDENT_STATUSES` (line 35) is
  **unchanged** — `standdown` deliberately stays out of it, since standing
  down cleanly is not itself a failure to alert on.
- **`tests/test_scheduled_run_detector.py`** (new `StanddownStatus` class,
  3 cases): `INCIDENT_STATUSES` excludes `standdown` (direct assertion); a
  `standdown` run is accepted end-to-end, persisted with that exact
  status, produces zero alerts, and is never queued for delivery; a
  control case confirms a genuinely unknown status is still a hard
  `DetectorError` — this widens the accepted set by exactly one value; it
  does not loosen validation generally.
